## 方法论（批复原文的工程化转译）

- **双向开工**：从大局（最终目标）与小节（参数、基础数据）两端同时修建，最后精确对接。
- **中间参数只摆位、不定值**：什么参数定多少属于"超纲"，先把字段、默认草案值、存储位置摆出来，避免一步走一步的链条式试错把项目拖死。
- **分工**：用户负责决策、主动性与创造性，响应遗漏/矛盾/歧义/恶性代码/偏题；AI 负责代码实现，以及评价"做得对不对、有没有走歧路"。
- **编辑器处理绝大部分配置事项**；运算（随机、绘图读取、机制）不依赖编辑器，由代码完成。

## 胜利条件（classic 0.0.1）

- 一座城市的基础数据能够正常编辑（编辑器）；
- 文本与 UI 正常显示（含本地化名、城市基础数据）；
- 基础气候与城市数据做好；
- 无气候现象的**随机种子搭台**完成，且结构可对接后续的气候现象。

达标即视为 0.0.1classic 收官。

### m3（候选）——搭台接入引擎

- 世界三层种子进入随机流：年度种子 → 现象总体影响与补偿系数；月度种子 → 现象分配数量与出现日期（正态离散，σ 来自 phenomena_spread_days）；日期种子 → 现象状态波动
- 城市噪点安放：相近经纬度 → 相近气候偏差；海拔做特定时刻各日间同期的随机差异
- 月内波动生效：month_temp_sigma + month_smoothing（"这个月每天正负多少度；让它稳定或平滑一些"）
- 月总量对账：monthly_total_strength（"凑齐降水和月积温"，雨天先验改用平均降水天数）

### m4（候选）——气候现象引擎

- 现象起源/出现/逐年行径（origin 字段消费：纬度带、环境、季节窗口、p_per_day）
- 现象间关系（互斥/接续/促进）
- 异常雨热三步中和（批复口径）：世界年度种子给补偿平面（AB）→ 总体削弱/增强反哺（B）→ 其余日期变极端（A）→ 三步在不随机时相加完全抵消，回归历史气候数据
- 目标：**有灾害，但灾害藏在统计表背后**（旱年/涝年/灾年，而月度表依然好看）

### m5（候选）——地图与倍乘

- 内部用矢量地图：用户拖点/画笔/移动，绘制气候现象与地形阻挡；主体只负责表现
- 经度正负相连（噪点已在圆筒面采样上实现，地图沿用同一坐标映射）
- 城市"气候表现-*"行作为现象影响的倍乘通道（需要定：哪一行乘哪一个量——待用户定语义）
